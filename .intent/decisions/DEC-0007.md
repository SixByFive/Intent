## Context

`intent agent prepare <task>` and `intent agent review` are designed to be called sequentially in an agent workflow. Review needs to know what task was being worked on, but the two commands are separate processes — there is no shared state between them.

Options considered:
- Pass task as an argument to `review` (forces agent to remember it)
- Environment variable (lost when the shell exits)
- A session file in `.intent/`

## Decision

`prepareAgentContext` writes a `.intent/.agent-session.json` file containing `{ task, preparedAt }` after every call. `reviewAgent` reads this file and includes `task` in the `AgentReviewReport`. The file is best-effort — write failures are silently ignored and review falls back to `task: null`.

The session file is excluded from git via `.intent/.gitignore` (same as the links index).

## Consequences

- Review can report which task is being reviewed without the agent needing to re-specify it
- Session is scoped to the `.intent/` directory — multiple repos have independent sessions
- The session decays naturally; it only reflects the most recent `prepare` call
- `preparedAt` timestamp allows tools to warn if the session is stale (not yet implemented)
