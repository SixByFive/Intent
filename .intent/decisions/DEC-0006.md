## Context

The existing export targets (`claude`, `cursor`, `copilot`) all produce markdown blocks. Markdown is readable for humans and LLMs, but AI agents that parse exported context programmatically have a harder time extracting structured data from prose. Research indicated agents benefit from semantic HTML structure — CSS selectors, `data-*` attributes, and embedded JSON make context more machine-traversable without sacrificing human readability.

## Decision

Add an `html` export target that produces a self-contained `intent-context.html` file. The file has three layers:

1. **Embedded JSON blob** (`<script type="application/json" id="intent-data">`) — full structured context for programmatic access
2. **Semantic HTML sections** — `<section id="plans">`, `<section id="decisions">` etc. with `<article data-id data-status data-system>` per record
3. **Rendered body content** — markdown-to-HTML conversion of each record's body for human readability

The file is always overwritten on export (no marker upsert logic needed).

## Consequences

- Agents can extract structured data via `#intent-data` JSON without parsing prose
- `data-*` attributes allow CSS-selector-based filtering (e.g. `[data-status="active"]`)
- No new dependencies — HTML is generated with string templates; markdown conversion is a thin inline function covering headings, lists, bold, italic, code
- The `intent export html --watch` pattern keeps the file current during active development
