## Context

CLI commands can easily accumulate logic over time, making it hard to test and reuse that logic from other consumers (e.g. the MCP server). We wanted the MCP server and CLI to share the same behaviour without code duplication.

## Decision

`packages/cli` is a pure presentation layer. Command handlers do exactly three things: resolve the git root, call a `core` function, format and print the result. No business logic lives in CLI command handlers.

## Consequences

- MCP server and CLI share identical behaviour because both call the same core functions
- Core functions are fully testable without a CLI harness
- Adding a new interface (e.g. a web API) requires no changes to core
- CLI commands are short and easy to audit
