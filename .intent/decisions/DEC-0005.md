## Context

We needed runtime validation of `.intent/` files (since they are hand-edited markdown) and TypeScript types for all file structures. Maintaining both separately causes drift.

## Decision

Zod schemas in `packages/schemas` are the single source of truth. TypeScript types are always inferred with `z.infer<typeof Schema>` — never written by hand. Validation happens on every file read via `parseFrontmatter`.

## Consequences

- Schema and type are always in sync — no drift possible
- Every `.intent/` file is validated on read; corrupt or hand-edited files produce clear `VALIDATION_ERROR` results
- `packages/schemas` has no dependencies on other packages — it can be imported anywhere
- Adding a new field requires updating only the Zod schema; the TypeScript type updates automatically
