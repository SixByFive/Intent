## Context

We needed a file format for `.intent/` files that is machine-readable for validation and querying, but also human-readable and editable without tooling. Options considered: pure JSON, pure YAML, custom DSL, hybrid frontmatter markdown.

## Decision

Hybrid frontmatter markdown: YAML frontmatter for structured data (validated by Zod), free-form markdown body for reasoning. This is the format used by Jekyll, Hugo, and many static site generators — it is widely understood.

## Consequences

- The YAML frontmatter is the contract; Zod validates it on every read
- The markdown body is unconstrained — humans write reasoning, not structured data
- Files are readable without tooling (plain text, standard format)
- AI agents can parse both the structured fields and the reasoning prose
- `gray-matter` handles parsing; no custom parser needed
